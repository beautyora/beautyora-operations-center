# 운영센터 v2 전환 가이드 (Google Sheets → Notion)

## 1. 무엇이 바뀌었나

| 예전(v1, `main` 8960924) | 지금(v2) |
|---|---|
| 시트 25개 이상(브랜드 미러, 접수·검토, 상품 접수, 상품 마스터, 파일 목록, 파트너 링크, 알림, 처리 이력, 거래조건, 간편 입출고 등) | 시트 없음. Notion DB 8개 + Drive |
| 폼 → 시트 → 수동 승인 → Notion 생성 → 시트로 다시 미러링 | 폼 → Notion `접수·검토` 페이지 바로 생성 |
| 상품 제출 → 시트 `상품 접수`에 JSON 저장 → 승인 시 Notion 반영 | 신규 제출은 Notion 페이지에 바로 저장(검수 대기), 승인 상품 수정은 페이지 본문에 변경 요청으로 저장 |
| 파일 목록 시트 | Drive 파일 자체의 `appProperties` |
| 알림·처리 이력 시트 | Apps Script 실행 로그 + Notion 댓글(검수 결과 등) + 오류 시 관리자 메일 |
| 화면에서 부를 수 있는 서버 함수 약 60개 | `api()` 1개(요청마다 권한 확인) |
| CSS 8개 세대가 겹친 110KB, 색 약 300개 | 토큰 기반 디자인 시스템 1개 |

## 2. 전환 순서(운영 환경)

1. **테스트 환경에서 먼저**: 작업 브랜치를 test로 배포 → 테스트 Notion DB 속성 연결 → 설정 → 초기 설정 → 링크 발급·상품 제출·검수를 한 번씩 해 봅니다.
2. 운영 Apps Script 스크립트 속성 추가
   - `BO_NOTION_TOKEN` (없으면 기존 `NOTION_TOKEN`을 그대로 씀)
   - `BO_NOTION_BRAND_DATA_SOURCE_ID`, `BO_NOTION_PRODUCT_DATA_SOURCE_ID`, `BO_NOTION_ACTIVITY_DATA_SOURCE_ID`
   - `BO_ROOT_FOLDER_ID`, `BO_GOOGLE_FORM_ID`, `BO_PARTNER_WEBAPP_URL`, `BO_ADMIN_EMAILS`
3. PR → `main` 머지 → production 배포
4. 운영센터 → **설정 → 초기 설정 실행**
   - 예전 트리거(`handleBrandFormSubmit`, `scheduledBeautyoraSync`, `onOpenProductSubmission` 등)는 이때 자동으로 지워집니다. 지우지 않으면 없는 함수를 호출하며 계속 오류가 납니다.
5. **설정 → 기존 시트 데이터 이관 → 미리 보기 → 이관 실행**
   - 사용 중인 상품등록 링크: 같은 토큰으로 Notion에 옮기므로 **이미 브랜드에 보낸 링크가 그대로 동작**합니다.
   - 파일 목록: 각 Drive 파일에 브랜드·상품·분류·상태 정보를 붙입니다.
   - 처리 중(신규 제출·검수 중·보완 필요)인 상품 접수: Notion 상품의 검수 상태·변경 요청으로 옮깁니다.
   - 4분 넘게 걸리면 멈춥니다. "모두 끝났습니다"가 나올 때까지 다시 누르면 이어서 진행합니다.
6. **설정 → 기존 제출 자료 가져오기** (운영센터 이전에 브랜드가 직접 올린 Drive 폴더가 있을 때)
   - 폴더 주소를 넣고 **미리 보기**로 `[BO-0001 · BO-0002] 회사_브랜드` 폴더와 브랜드 연결, 파일 분류(사업자등록증·통장사본·계약서는 Notion 연결, 나머지는 폴더 보관)를 확인한 뒤 **가져오기 실행**
   - 파일은 브랜드 자료 루트 폴더로 한꺼번에 **복사**되고(원본 유지), Notion 브랜드의 `구글 드라이브`에 그 폴더 링크가 걸립니다(비어 있거나 원본 폴더를 가리키던 링크만 교체).
   - 중요 서류(사업자등록증·통장사본·계약서)만 해당 서류 URL 속성의 **빈 칸**에 연결하고, 상품 리스트·소개서 등 나머지는 폴더에만 둡니다. 가져온 서류는 `승인 완료`로 등록되어 서류 검수 대기열에 쌓이지 않습니다.
   - 예전 실행에서 원본 폴더 안에 생긴 사본은 다시 실행하면 브랜드 자료 폴더로 옮겨집니다.
   - 코드가 없는 폴더는 이름이 브랜드명·회사명과 한 곳만 일치할 때 연결합니다. 여러 번 실행해도 이미 복사한 파일은 건너뜁니다.
7. 연결 상태가 모두 "정상"이면 예전 스프레드시트는 **보관용으로만** 둡니다(삭제하지 않음).

## 3. 주의할 점

- Notion 통합(Integration)을 8개 DB 모두에 연결해야 합니다. 새로 만든 `상품등록 링크` DB는 통합이 만든 것이라 자동으로 연결됩니다.
- 댓글 기능(검수 결과·재접수 기록)을 쓰려면 통합에 **댓글 읽기·쓰기** 권한을 켜 주세요. 없어도 동작은 하고 댓글만 빠집니다.
- 영업 기록의 `상담 담당자`(사람 속성)는 통합에 **사용자 정보(이메일) 읽기** 권한이 있을 때만 채워집니다. 없으면 내용 끝에 작성자 이메일이 남습니다.
- `입출고 이력`의 `수량 (+/-)`는 출고를 음수로, `입출고 방향`은 +/−로 함께 기록합니다. Notion의 `반영 수량` 수식이 방향을 한 번 더 곱한다면 수식을 확인해 주세요(현재 DB에는 출고 기록이 없어 확인하지 못했습니다).
- 운영센터(직원용 배포)는 **접속한 직원 권한**으로 실행됩니다. 직원 계정이 브랜드 자료 루트 폴더와 입점 신청 폼에 접근 권한(편집자)이 있어야 폴더 열기·폼 가져오기가 됩니다. 브랜드용 배포는 소유자 권한으로 실행됩니다.
- `BO_ALLOW_EMBED`: v1은 모든 사이트에서 iframe으로 넣을 수 있었습니다(클릭재킹 위험). v2는 기본으로 막습니다. Notion·Google Sites에 넣어 쓰고 있었다면 `true`로 설정하세요.

## 4. v1에서 발견해 고친 문제

| 심각도 | 문제 | v2 |
|---|---|---|
| 높음 | 권한 확인 없는 공개 함수(`testProductCatalog`, `runBeautyoraSync`, `createApprovedBrands`, `installBeautyoraTriggers`, `setupBeautyoraSystem` 등)를 브랜드용 링크(소유자 권한 실행) 화면에서 누구나 호출 가능 | 공개 함수는 `api()`와 소유자·트리거 전용 5개뿐, 테스트로 고정 |
| 높음 | 같은 이름 함수 중복(`onOpen` 2개, `find_` 2개) → 한쪽 메뉴가 사라짐 | 해당 코드 삭제, 중복 검사 |
| 중간 | 구버전 제출 경로가 상품ID의 브랜드를 확인하지 않아 다른 브랜드 상품 덮어쓰기 가능 | 모든 제출에서 Notion 브랜드 관계 확인 |
| 중간 | 운영 시트·폴더 ID가 코드에 고정(`제목 없음.gs`, `Code.gs`) → 테스트 환경이 운영 데이터를 건드릴 수 있음 | 코드에 운영 ID 없음 |
| 중간 | 링크 만료일 형식이 다르면 만료되지 않음 | Notion 날짜 속성 + 문자열 비교 |
| 중간 | 브랜드 데이터가 Notion↔시트 양쪽에 있어 불일치 | Notion 한 곳 |
| 낮음 | 화면 코드가 여러 파일에서 서로 덮어쓰는 구조, 압축된 한 줄 코드 | 관리자·브랜드 화면 각 1개 파일 |
| 낮음 | 테스트 함수에 운영 데이터 수치(브랜드 107개 등) 고정 | 가짜 Notion으로 20개 서버 테스트 + 브라우저 테스트 |

## 5. 디자인에서 고친 점

- **색·크기 체계**: 예전 CSS에는 서로 다른 시기의 스타일 8개 묶음이 겹쳐 있었고 색이 약 300개, 반응형 기준 폭이 20개 가까이 흩어져 있었습니다. 애플식 회색·베이지·파랑 강조가 화면마다 섞였습니다. → 토큰 1세트(바탕·글자·선·브랜드색·상태색 4종), 기준 폭 2개(1024px, 720px).
- **전체 화면을 막는 로딩창**: 저장·조회마다 화면 전체를 흐리게 덮었습니다. → 누른 버튼에만 진행 표시, 목록은 뼈대(스켈레톤) 표시.
- **깊은 링크 없음**: 새로 고침하면 항상 홈으로 돌아갔습니다. → `#/brands/BO-0001?tab=activity`처럼 주소로 바로 이동, 뒤로 가기 동작.
- **긴 입력 폼**: 짧은 값(담당자·연락처)도 큰 글상자로 보였습니다. → 짧은 글은 한 줄, 자주 쓰는 항목 먼저, 나머지는 접기.
- **상태 표시 일관성**: 같은 상태가 화면마다 다른 색이었습니다. → 상태 이름 → 색 한 곳에서 관리.
- **모바일**: 표가 화면 밖으로 밀리던 부분 정리, 390px 폭에서 가로 스크롤 없음을 테스트로 확인.
- **접근성**: 아이콘 버튼 이름, 키보드 포커스 표시, Esc로 닫기, 움직임 줄이기 설정 반영.

## 6. 기능 제안

### 새로 넣었거나 넣을 만한 기능
- ✅ **변경 요청 비교표**: 승인된 상품을 브랜드가 고치면 "현재 → 변경"만 보여 주고 승인 시 반영(이번에 구현).
- ✅ **후속 연락 알림판**: 영업 기록의 후속 확인일이 오늘 이전이면 홈에 모음(구현).
- ✅ **링크 만료 임박 표시**, **Notion "확인 필요" 재고 모아 보기**(구현).
- ✅ **오류 메일 알림**: 6시간마다 연결 점검 후 오류가 있으면 관리자에게 메일(구현).
- 제안: **브랜드에게 검수 결과 메일** — 보완·반려 시 브랜드 이메일로 사유와 링크 발송(현재는 브랜드가 링크에 들어와야 확인 가능).
- 제안: **상품 일괄 승인** — 같은 브랜드의 신규 상품 여러 개를 한 번에 승인.
- 제안: **Notion 보기(View) 순서로 목록 정렬 저장** — 직원별 자주 쓰는 필터 저장.

### 없애거나 줄여도 될 기능
- ❌ **브랜드 전체 목록 시트 미러링**: Notion이 원본이 되었으므로 불필요(삭제).
- ❌ **간편 입출고·거래조건 시트**: Notion `입출고 이력`, `벤더 동일 상품 조건`과 중복(삭제, Notion으로 연결).
- ❌ **알림·처리 이력 시트**: 실행 로그와 Notion 댓글로 대체(삭제).
- ❌ **시트 방식 상품 제출(업체별 제출 시트 복사)**: 상품등록센터로 대체(삭제).
- ❌ **엑셀 수집 작업 큐(opsImport)**: 브랜드 화면의 엑셀·CSV 가져오기로 대체(삭제).
- 검토 권장: **상품 DB의 `검토 상태`(자료 수집/추천…)와 `등록 검수 상태`가 따로 있음** — 영업 검토와 등록 검수가 다른 뜻이면 유지, 같다면 하나로 합치는 것을 권장.
- 검토 권장: **상품 DB의 빈 속성 `파일과 미디어`(전화번호 형식)**, `바코드`(숫자)와 `바코드(텍스트)` 중복 — 정리 권장. 숫자 바코드는 앞자리 0이 사라집니다.
- 검토 권장: 브랜드 DB의 `판매 채널` 선택지 중복(`백화점 · 면세점`과 `백화점`/`면세점`, `스마트스토어`와 `네이버 스마트스토어`) 정리.
