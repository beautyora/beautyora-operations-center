# 운영센터 최적화 및 회귀 검증

기준: `main` b6210c8 → `audit/main-optimization` (2026-09-27).

## 변경 내용

- 성공한 저장 요청 후 브라우저 읽기 캐시 무효화. 실패·검증 오류에서는 캐시 유지.
- 입출고 저장은 잠금 안에서 읽은 상품·장소·입출고 목록을 재사용. 전체 상품 구성 호출 3회 → 1회.
- 상품 제출은 헤더를 한 번 읽고 신규 행을 한 번에 저장. 제출ID 기반 재시도와 부분 실패 복구 유지.
- 브랜드 상품 탭·파트너 상품 조회는 최종 브랜드에 속한 상품만 JSON 해석·병합·정렬. 마스터 덮어쓰기 규칙 유지.
- 홈 최근 활동은 로그 끝에서 최대 100행씩 역방향 조회. 빈 행을 건너뛰고 기존과 동일한 최근 8개 반환.
- 엑셀 수집은 예약/최종 저장에만 공용 잠금 사용. Drive 변환·파싱·임시 파일 정리는 잠금 밖에서 수행.
- 엑셀 재시도 시 변환된 시트 ID가 바뀌어도 시트명·원본행·자료JSON으로 이미 저장한 행을 확인하여 중복 방지.

## 자동 검증

```sh
node tests/optimization.test.cjs
node tests/performance-regression.test.cjs
```

기존 환경 격리·브랜드 링크·요청별 시트 재사용 검사와 14개 회귀 검사 그룹을 실행한다.
회귀 검사에는 기존 파트너 UX 검사 15개도 포함한다.
GitHub Actions에서 push/PR마다 실행하며 Apps Script 배포 전에도 실행한다.

주요 모의 검증 결과:

| 대상 | 확인 |
|---|---|
| 거래조건 저장 | 실제 프런트 서버 래퍼 경유 후 캐시 버전 1 → 서버 버전 2 반영 |
| 입출고 | 상품 조회 1회, 재고 초과 출고 차단, 동일 요청 재시도 중복 방지 |
| 300개 상품 | 헤더 읽기 1회·배치 쓰기 1회, 재시도 시 신규 행 0개 |
| 로그 10,000행 | 헤더 1행 + 마지막 100행 조회로 동일한 최근 활동 반환 |
| 상품 조회 | 브랜드별 결과와 전체 결과를 필터링한 결과 동일 |
| 엑셀 | 잠금 밖 Drive 처리, 동시 수집 차단, 예약 해제, 완료 로그 실패 후 재시도 |
| 비동기 캐시 | 요청 중복 제거, 저장 전 응답이 캐시를 다시 채우지 않음 |

위 수치는 모의 환경의 호출·행 수이며 운영 응답시간 개선률이 아니다.

## 테스트 환경에서 확인할 항목

1. 이 브랜치를 `target=test`로 배포하고 기존 테스트 URL을 새로고침한다.
2. 홈, 브랜드 목록, 브랜드 개요/상품/재고/파일 탭 및 입출고 화면을 연다.
3. 테스트 데이터로 거래조건을 저장하고 즉시 표시 및 재열기 결과를 확인한다.
4. `testBrandWorkspace`, `testBrandCommerce`, `testStaffPerformance`를 테스트 프로젝트에서 실행한다.
5. 테스트용 첨부/상품 및 엑셀만 사용해 저장·재시도를 확인한다.

## 남은 제약

- Google Sheets 전체 읽기가 모두 제거된 것은 아니다. 상품 원시 데이터와 제출자료 페이지의 식별 열은 계속 전체 범위를 읽는다.
- 지속적인 서버 캐시는 추가하지 않았다. 외부에서 직접 수정한 시트의 최신성과 재고 검증을 유지한다.
- 비정상 강제 종료로 엑셀 수집 예약이 남으면 30분 후 재시도 가능하다. 정상 오류 경로에서는 즉시 예약을 해제한다.
- 한 번에 매우 큰 XLSX를 처리하면 변환·파싱 자체의 실행시간 한계는 남는다.
- 운영 배포 및 메인 병합은 별도 승격 단계다.
