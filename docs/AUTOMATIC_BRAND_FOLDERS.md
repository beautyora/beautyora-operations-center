# 신규 브랜드 Drive 폴더 전환

## 확인 범위

운영센터 main `89c10679fb2461d4556cb1ddc464fd894c1ebe8c`(PR31), 브랜드 랜딩 main `a0c5c82`를 확인했다. 랜딩 `google-apps-script/form-bridge.gs`는 `FormResponse.submit()` 후 반환한다. 중복 확인 → Notion 등록 → BO ID 발급을 담당하는 별도 프로젝트 소스/ID는 두 저장소에 없다. FormResponse.submit()이 form-submit 트리거를 실행한다고 가정하지 않는다.

이 변경의 범위는 **신규 Notion 페이지 + 확정 BO ID → Drive**다. 등록 함수 내 동기 실행이 아니라 기존 1분 트리거 감지이며, Apps Script 지연/오류 시 더 늦어질 수 있다. 랜딩 → Notion E2E는 별도 등록 프로젝트 확인이 필요하다. 랜딩 저장소는 변경하지 않는다.

## 보호 장치

초기 설정은 `BO_BRAND_FOLDERS_START_AT`에 UTC ISO 시각을 최초 한 번 저장한다. 재실행해도 유지한다. 기준점이 없으면 트리거/지금 처리는 안내만 반환한다. 기준점 이후 생성되고 Drive URL이 비어 있는 브랜드만 자동 대상으로 삼는다. 브랜드명과 BO-숫자 4자리 이상 ID가 필요하며 ID 발급이 늦으면 다음 실행에서 재확인한다. 중복 ID는 오류로 중단한다.

기존 미연결 83개 브랜드는 소급 생성하지 않는다. 과거 페이지는 수정되어도 자동 대상이 아니며 필요할 때 개별 폴더 버튼으로 처리한다. 기준점을 임의로 과거로 이동하지 않는다.

새 폴더는 `브랜드명 (BO-####)` 아래 `01_섬네일`, `02_상세페이지`, `03_서류`다. 기존 `01_상품 이미지`는 그대로 재사용하고 이름/내용/링크를 보존한다. 기존 URL, 재시도 기록, 루트의 동일 BO ID 폴더(기존 `[BO-####] 이름` 포함) 순으로 재사용한다. 여러 후보면 중단한다. 공개 링크 권한을 추가하거나 기존 권한을 변경하지 않으며 새 폴더는 상위 권한을 상속한다.

전역 잠금으로 버튼/트리거를 직렬화한다. 하위 폴더와 선택 양식 복사 전에 `BO_BRAND_FOLDER_PENDING_<page ID>`에 폴더 ID를 저장한다. 준비 후 마지막에 Notion URL을 기록하고 pending을 지운다. 실패하면 다음 실행에서 재사용/보완한다. 이미 URL이 있는 브랜드는 자동 처리하지 않으며 개별 API로 누락 하위 폴더를 보완할 수 있다. 폴더와 상품 데이터 삭제는 없다.

## 정확한 배포 순서 (이번 작업에서 실행하지 않음)

1. PR 코드/모의 테스트 검토. 테스트 Notion/Drive와 운영 설정의 분리를 확인한다.
2. Actions → **Apps Script 배포** → 작업 브랜치 → `target=test`, `mode=existing`, 설명 입력 → 실행. `TEST_SCRIPT_ID`, `TEST_DEPLOYMENT_ID`, `CLASPRC_JSON_BASE64`가 필요하다.
3. 테스트 프로젝트 소유자/관리자가 `setupBeautyora` 또는 설정 → 초기 설정 실행. 기준시각 속성과 `scheduledBrandFolders` 1분 트리거를 확인한다. 기존 트리거는 중복 설치하지 않는다. 초기 설정은 기존 기능상 알 수 없는 과거 트리거를 제거하므로 사전에 핸들러 목록을 확인한다. 별도 등록 프로젝트에서 실행하지 않는다.
4. 테스트 DB에서 전환 전 브랜드 무변경, 전환 후 신규 페이지의 ID 지연, ID 확정 후 폴더/URL, 재시도/기존 폴더 재사용을 검증한다. 운영 DB에는 테스트 브랜드를 만들지 않는다.
5. 승인 후 merge. Actions → **Apps Script 배포** → `main`, `target=production`, `mode=existing`, 설명 입력 → 실행. `PROD_SCRIPT_ID`, `PROD_DEPLOYMENT_ID`, 인증 Secret이 필요하다. 보고된 운영 버전106은 이 작업에서 변경하지 않았다.
6. 운영 소유자가 초기 설정을 한 번 실행해 전환 시각을 확정한다. 배포와 설정 사이에 등록된 페이지는 자동 대상이 아니므로 해당 기간 실제 신규 브랜드만 개별 처리한다. 시간 트리거는 프로젝트 최신 코드를 실행하므로 웹앱 버전 갱신과 별개다.
7. 연결 상태/트리거 실행 기록 및 다음 실제 신규 브랜드의 폴더·URL·공유 상속 상태를 확인한다. 기존 83개 미연결 브랜드 무변경을 확인한다. 실패는 로그 및 기존 관리자 알림으로 확인한다.
8. 배포 확인 이후 부모 작업에서 Notion `드라이브 폴더 만들기` 속성 실제 삭제를 조율한다. 이 PR은 코드/UI 스키마 의존성만 제거한다.

## 중지·복구

중지 시 운영 프로젝트의 `scheduledBrandFolders` 트리거만 중지/제거한다. 기준시각, pending 속성, 폴더/URL을 보존한다. 재개 시 초기 설정은 기준점을 유지하고 미완료 신규 건을 따라잡는다. 웹앱 배포 버전만 롤백하면 시간 트리거 소스는 그대로다. 트리거를 중지한 뒤 승인된 소스도 복원해야 한다. 체크박스 삭제 이후 과거 버전의 트리거를 무심코 재개하지 않는다.
